# Visual architecture: fixed stage, art catalogue and studio

Status: **built and tested** (development environment and the family's Windows, 17/11/2026). Stage 2 (realistic photography, new pieces in the catalogue, victory clip, OpenAI adapter checked) is described in section 10. What could not be checked yet is in section 9.

## 1. Goal

- Give the app a studio look: illustrated scenery, pieces consistent with each other, the same presentation in every game.
- Eliminate by construction the defect of pieces out of place when the window changes size.
- Allow the art to come from three origins (generated by API, ready-made packs, built-in art) without the game knowing the difference.
- Keep what already worked: curriculum, adaptive engine, server-side evaluation, handwriting reading, local database.

## 2. Decisions

| # | Decision | Reason |
|---|---|---|
| D1 | Each game screen is drawn on a **fixed 1920×1080 stage** and scaled up or down by a single factor (`apps/game/src/stage/Stage.tsx`) | Positions no longer depend on the window |
| D2 | Positions live in **data** (`content/scenes/*.json`): zones, objects, piece sizes | Changing the layout of a screen means changing numbers, not logic |
| D3 | The stage is drawn in **HTML/CSS by React**, not by Phaser | It was the technique checked before construction; it keeps text sharp and the keyboard accessible, and did not require rewriting the game logic. Phaser remains only in the paper adventure |
| D4 | The game requests art by **logical name** (`orchard.crate`) from a **catalogue**; with no approved version, the card's built-in art is used | The game never breaks for lack of an image; the art changes gradually and without restarting |
| D5 | Generation happens **outside the game**, in the parent area, and only enters the game after **parent approval** | The child never sees an unreviewed image nor triggers a cost |
| D6 | The image provider sits behind an **adapter** (`packages/art/src/providers.ts`) | The Claude API does not generate images; the provider may change |
| D7 | Claude has two roles: **drafting the request** and **checking each candidate** | Checked with real calls |
| D8 | Margin cropping and conversion to WebP are done **by the browser** at approval time | The family PC only has the portable Node; no extra installation |
| D9 | A **single style guide** goes into every request; a character has a **master image** that serves as the reference for the other poses | Without it every image comes out with a different face |
| D10 | A box's slots are computed from a **grid with margins** stored with the art; the margins are adjusted on the approval screen, with the 10 fruits in view | A generated box never has its interior in the same place as the built-in one |

Change from the proposal: D3 planned Phaser, and the spending limits were in money. It became HTML/CSS, and the limits count **images**, because the price per image was not confirmed.

## 3. Layers

```
Shell (React)          game catalogue, parent area, art studio
Stage                  1920×1080, single scale; common bar, guide, panels and keyboard (games/shell.tsx)
Scene (content/scenes) zones and sizes of each game, in stage points
Geometry (shared)      boxes, slots and fruits computed and tested without a browser (packages/shared/src/stage.ts)
Game rules             round, attempts, hints; server-side evaluation
Art catalogue          logical name -> approved version or built-in art (stage/art.ts, /api/art/catalog)
Production line        card -> request -> generation -> check -> approval -> catalogue (apps/server/src/art.ts)
Adapters               image API (OpenAI or simulated), Claude API, pack reader (packages/art)
Local data             SQLite + files in data/art, all on the PC
```

## 4. Scene and cards

- **Le potager qui écoute** (`content/scenes/listen-garden.json`, 18/11/2026): garden background, a big speaker button at
  the top and three card layouts (3, 4 and 6 pictures). The pictures are system emoji (Segoe UI Emoji on Windows) or
  numerals, so no download was needed. The 6-picture layout has two rows that stay above Lila's bubble.
- **Home screen with 9 games:** the cards go to 5 per row (class `lots`), so they still fit above «Sur papier».

- `content/scenes/<game>.json`: background, zones (`pile`, `crates`, `panel`…) and sizes, all in stage points. There is one per game.
- `content/art/specs.json`: style guide and one **card** per image (subject, size, transparency, prohibitions, built-in art, slot grid, character reference).
- Scenes and cards enter the app at build time. Changing one of them requires rebuilding; the tests check that they are consistent.

## 5. How to use the studio (parent area, «Art du jeu» tab)

1. Fill in `.env`: `IMAGE_PROVIDER=openai` and `IMAGE_API_KEY=` (the image provider's key). Close and reopen the app.
2. Tick the consent and turn generation on. Adjust the daily and monthly image limits, if you like.
3. Open a card. Check or edit the request; the «Demander à Claude de rédiger» button writes an English version based on the style guide.
4. «Générer des candidates» (1 to 4). The screen updates by itself.
5. Each candidate shows the technical check and Claude's check. «Refuser» or «Approuver…».
6. On approval, the browser crops and converts the image. For the box, adjust the margins until the 10 fruits fit. Confirm.
7. The game starts using the art immediately. In each card you can go back to a previous version or to the built-in art.

Recommended order for a character: approve **Lila (standing)** first; the other poses can only be generated afterwards, because they use that image as a model.

To just try out the screen, at no cost: `IMAGE_PROVIDER=mock` generates test shapes (the third one comes out defective on purpose).

## 6. Ready-made packs

- Put the unzipped folder in `assets\packs-inbox\<pack-name>\`, with the licence file inside.
- In the studio, «Chercher des paquets». The app reads PNG, WebP and JPEG, and also MP4 and WebM clips for the clip card (up to 600 files per pack). It keeps the beginning of the licence file.
- Inside each card, the pack images appear for choosing. The chosen one becomes a version like any other, with the pack's credit.

## 7. Data, routes and configuration

**Database (migration 3; only adds tables; automatic backup first):**

| Table | Content |
|---|---|
| `art_prompts` | saved request for each card (edited by the parents or drafted by Claude) |
| `art_jobs` | each generation: card, provider, model, request used, state, error |
| `art_candidates` | each image received: file, hash, dimensions, technical check, Claude's verdict, decision |
| `art_assets` | approved versions: card, version, file, origin, credit, grid margins, active or not |
| `art_packs`, `art_pack_files` | packs read and their images |

**Files:** `data/art/candidates/` and `data/art/approved/`, with names generated by the server. Only files registered as approved are served to the game (`/art-files/…`).

**Routes:** `GET /api/art/catalog`, `GET /api/art/studio`, `PATCH /api/art/specs/:id/prompt`, `POST …/prompt/draft`, `POST …/generate`, `POST …/activate`, `GET /api/art/candidates/:id/image`, `POST …/review`, `POST …/approve`, `POST …/reject`, `PATCH /api/art/assets/:id/grid`, `POST /api/art/packs/scan`, `GET /api/art/pack-files/:id/image`, `POST …/use`. Those that change data require the app header and a local origin, like the others.

**Configuration (`.env`):** `IMAGE_PROVIDER` (`openai`, `mock` or empty), `IMAGE_API_KEY`, `IMAGE_MODEL` (default `gpt-image-2.5-sunburst`), `IMAGE_QUALITY` (default `medium`). The keys stay only on the server; the browser never talks to providers.

**Privacy and content:** no request carries the child's name, photo or answer (there is a test for this); the style guide forbids existing characters, real people, text and brands; every image goes through the parents before appearing in the game.

## 10. Stage 2 (17/11/2026)

### 10.1 Realistic style (2a)
- The style guide (`content/art/specs.json`, «Verger de Lila — photographie») asks for **realistic photography**: natural morning light, real textures, no drawing, stylized 3D or toy-like look, and animals without clothes or human postures.
- All cards were rewritten as photos of real things (McIntosh apple, harvest crate, cotton gingham tablecloth…).
- **Lila** is a real European hedgehog, always on all fours. The poses became **standing** (curious, snout raised), **happy** (quick little step, sniffing the air) and **attentive** (head tilted, sniffing the ground). The old «arms raised» and «paw on chin» were removed because they are human postures.
- The default request (`packages/art/src/prompt.ts`) starts with «Photographie de…» (or «Clip vidéo…») depending on the card type; since the translation, the default request is in French.

- Cards with `"drawnByCode": true` are pieces the game draws in CSS. The game only switches to the photo when there is an **approved** version (`approvedArt()` in `apps/game/src/stage/art.ts`); the `fallback` of these cards (`/art/scene/pond.svg`, `lilypad.svg`, `wagon.svg`) only illustrates the card in the studio.
- With a photo, the piece becomes a background image and the numbers (lily pad, wagon) get a legible white badge.

Stage 3 added `path.stone` (path stone, drawn by code without a photo) and `path.basket` (finish basket; built-in: `/art/basket.png`), used by *Le chemin des nombres*. The prompts for generating outside the app are in [art-prompts.md](art-prompts.md). With more than 5 games, the home screen shows 4 compact cards per row (`.cards.many`). *Les dominos des nombres* added `domino.table` (game scenery: wooden table; built-in: the orchard) and `domino.tile` (blank tile, drawn by code without a photo; dots, numbers, sums and rods are always drawn by the app on top). *Les mots cachés* added `hidden.sheet` (grid sheet, drawn by code without a photo) and `hidden.loupe` (magnifying glass; built-in: `/art/scene/loupe.svg`).

**Jardin de Lila (Phaser, `GardenScene.ts`):** scenery, remise, puits, potager, pousse, tournesol and Lila come from the cards
`garden.*` and `lila.idle` (`PhaserGame` waits for the catalogue and passes `{url, approved}` through the registry). The girl is still
drawn by code. There are two layouts: `DRAWN` (fallback drawing seen from above, the usual positions, used by the E2E) and
`PHOTO`. The latter applies when the photo scenery is approved: landscape in perspective, pieces on the lawn, the girl does not go
above `top` = 250 and grows as she gets closer to the camera. In both layouts, depth = base of the piece. If the parents
approve a scenery with a lower horizon, it is enough to adjust `PHOTO`.

**Celebration (`Confetti` in `games/shell.tsx`, CSS in `game.css`):**
- **Sizes:** in container units (`cqw`/`cqh`). That is why the same confetti works on the 1920×1080 stage and, with `fixed`, on the whole window (paper sheet card).
- **Size:**
  - `big` (2 cannons in the bottom corners and a long shower) only at **milestones**: level confirmed («🚀 Nouveau niveau N!»), weak point conquered («🌟 Point fort gagné!») and mission completed;
  - `small` = short shower on a correct round.
- **Sound** (`audio.ts`), all synthesized, with the volume lowering while the voice speaks:
  - `sfx.chime` on a correct answer (≤ 0.6 s);
  - `sfx.win` at the end of the activity (bell and applause, ≤ 2 s);
  - `sfx.celebrate` only at milestones (≤ 5 s); a tap on the panel skips the celebration (`sfx.hush`);
  - no sound on a mistake.
- **Applause before speech** (`cheerAfter` in `audio.ts`): at the end of the activity and at milestones, the applause plays in full (1.9 s at the end, 3.5 s at milestones) and only then does Lila speak. Before, they spoke together, and the applause was at 30 % under the voice, almost inaudible. A tap that skips the celebration brings the sentence immediately; leaving the game cancels the pending sentence.
- **Messages** (`praise.ts`): a short marker and, from time to time, the specific praise coming from the server; see `docs/testing.md`.
- **Weak point almost conquered** (`almost`): a discreet green line in the result panel and on the sheet card («🌱 Presque gagné…»), without big confetti.
- **Stars:** only on a correct answer (3 first time, 2 with a hint). On a mistake, no greyed-out star in view.
- **Hint:** «think before asking».
  - **Paper:** «Un indice ?» appears after 20 s with the sheet.
  - **Les mots cachés:** «Un indice» stays disabled («Cherche encore…») for 20 s, from the start and after each word found or each hint; one hint per word.
  - **Test:** the delay is shortened by the key `melina.hintDelayMs` (`apps/game/src/hints.ts`).
  - **Report:** «💡 Indice utilisé dans X % des réponses» per skill, highlighted above 30 %.
- **Home-screen cards:** badge «Niveau N · 🌻 N» (`.card-badge`) instead of the star total.
- **Server down:** the home screen shows a notice with «Réessayer» (`.home-offline`). When the server comes back, the page reloads so that the images that failed come back. The footer shows «Connexion…», not «Jeu prêt». On her screen, the voice appears only as «française (Canada)»; the technical name stays in the parent area («IA et données»).
- **Answer box** (`.answer-box`): `line-height: 1`. Before, the text line (104 px) was taller than the box (86 px). 4 digits fit (level 6).
- **Enter:** validates or continues, even with focus on a key, stone or option tapped with the mouse. It only respects a navigation button (little house, sound, «Accueil», «Un défi») when focus arrived via the keyboard (`:focus-visible`). A held (repeating) key does not count.
- **Report:** low-data notice (`.rp-lowdata`), «🌱 Presque gagné» box instead of «À garder à l’œil», section «🏡 À la maison» (`.rp-home`, with the notice in `.rp-warning`). The numbers at the top have no change pill.
- **Paper sheet card** (`FeedbackCard`): with a wrong answer in a mission, it shows «🌱 La graine t’attend…» and the button «On réessaie cette étape», instead of «Prochaine graine».

**Level 5 on screen:**
- **Domino:** the long sum shrinks the font, proportionally to the text length.
- **Story:** with more than 5 sentences, `.book.long` uses a 28px font.
- **Fishing:** the two-word label (`.fish span.long`) wraps onto two lines without being squeezed.
- **E2E:** opens the 7 games at level 5 and checks that nothing overflows.

**Stage that does not scroll:** `.stage-viewport` and `.stage` use `overflow: clip`. With `overflow: hidden`, the browser could still scroll the container when focusing or clicking an element (the blurred background extends 60 points beyond the window), and the screen ended up shifted and stuck. The E2E checks that scrolling is zero.

### 10.3 Victory clip (2c)
- New card type: **`clip`** (`lila.dance`). **MP4 or WebM** video, up to 40 MB, 2 to 6 s, looping. The app **does not generate video**.
- Input: folder in `assets\packs-inbox\<pack>\` → studio «Chercher des paquets» → card «Lila qui danse» → choose the video → confirm. Nothing goes in without approval.
- The type is checked by the **content** (`packages/art/src/video.ts`): MP4 with a video brand and WebM. HEIC/AVIF and generic Matroska are refused. An image card refuses video and a clip card refuses images. The server refuses to generate a clip (409 `clip-not-generated`).
- The server serves approved clips and images from disk, streamed and with **partial requests** (`Range`, 206 responses), as the browser needs to play and loop MP4/WebM. In the studio, the previews of pack clips stay still (only the beginning of the file is downloaded) and play on mouse hover.
- In the game (`Guide` in `games/shell.tsx`): on a correct answer, if there is an approved clip, Lila in the corner becomes `<video autoplay loop muted playsinline>`. **Always muted**, even if the file has sound. Without a clip, the current jump is used.
- `PACKS_DIR` (environment variable) changes the packs folder; it lets the tests use a temporary folder.

### 10.4 Image provider: OpenAI (2d)
Checked against the official documentation (developers.openai.com, *Image generation* guide and *Images* reference), 17/11/2026:
- `gpt-image-2.5-sunburst` (the app's default) exists, is the default model for edits in the reference and accepts `background: "transparent"` with `png`/`webp`. `gpt-image-2.6-sunburst/-flare` (04/11/2026) are newer, but the reference does not confirm transparency for them.
- Free size `WxH`: sides multiples of 16, aspect ratio up to 3:1, from 655 360 to 8 294 400 pixels. All cards fit (the pond, 1536×512, is exactly 3:1).
- References: `POST /v1/images/edits`, multipart field `image[]` (up to 16).
- Response always in `data[].b64_json`. Errors: 401 key; 403 region or unverified organization; 429 limit or lack of credit (`credit_balance_exhausted` etc.); 400 `moderation_blocked` (safety filter). The adapter now gives its own message for each.
- It may be necessary to **verify the organization** at OpenAI before using the GPT Image models.
- Estimated price per image (2.5, output only, 1024×1024): low ≈ US$ 0.006 · medium ≈ US$ 0.013 · high ≈ US$ 0.053. The app uses `medium` by default (`IMAGE_QUALITY`).
